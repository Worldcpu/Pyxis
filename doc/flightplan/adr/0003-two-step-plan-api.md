# ADR-0003：两步式计划 API（候选 → 生成）

- 状态：已接受（2026-08-06，grill 决策 6）
- 相关：[glossary.md](../glossary.md) 决策 6/7/9、[design.md](../design.md) §4

## Context

一次完整飞行计划的计算成本差异大：候选航路（仅算路，百毫秒）vs 完整 OFP（高度+燃油+风源，秒级）。且候选航路只在航路层面不同——油量/高度依赖"选中的那一条"。三个参照物（SimBrief/SFP/参考实现）的交互均为"先选航路再看结果"。替代方案是一步式（一次请求返回完整计划，内部自动选最优候选）。

## Decision

**两步式**：`plan.routes`（请求 10 字段 → 候选数组，k=5，不带 segments）→ 用户选定 → `plan.generate`（重发路由参数 + **route_string 统一输入**（迭代修订 2026-08-06：候选 index 有重算竞态，前端把选中候选的 route_string 传回，手写同路径；glossary 决策 23）+ 完整设置 → FlightPlan）。FlightPlan 保持单计划纯度（不可变值类型 + 燃油单次计算）。候选阶段不算油；seed 为内部机制（不带 = 确定性 k 最短路，"换一批"由 px 管理 seed，元数据携带复现）。`find_routes`（bf handler）不暴露，避免双入口漂移。

## Consequences

- 正向：交互符合参照物；候选阶段快；FlightPlan 干净；前端缓存策略简单（航路设置变重发 ①，油量设置变重发 ②）。
- 负向：generate 需重发路由参数（消息体较大，无状态代价）；若未来要"一键生成最优计划"需加薄壳端点（内部串 ①+②）。
- 权衡：无状态 API 换取复现性（seed）与前端缓存简单性；有状态会话模型被否决。
